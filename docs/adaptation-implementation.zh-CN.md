# hash-slinging-slasher 研究文档的本地实施记录

版本：CODNameFinder 2.1.0。日期：2026-10-05。

本文件对应 `hash-slinging-slasher-adaptation.zh-CN.md` 的 P0、P1、P2。软件保持 Avalonia NativeAOT 液态玻璃界面与自带 Python 工作进程，运行时不依赖研究项目、系统 Python、Rust、.NET 或 Git。本文描述实际代码与可重跑验证，不把参考项目的性能数字当作本机成绩。

## 剥离的正确性与边界

FNV 的乘数为奇数，在 `2^32`、`2^63` 或 `2^64` 模环内有逆元。FNV 一步的逆式为 `previous = (current × inverse_prime) XOR byte`；加法型 prime32 与 DJB2 XOR 使用各自的逆式。实现来自这些公开数学关系及本项目的既有前向算法，没有复制 GPL 项目的搜索源码。

原调研文档所说“63 位 ID 的最高位已知为 0”，只描述保存的 ID；它不能恢复前向哈希被截掉的完整状态最高位。本实现没有作这个假设。低 63 位对乘法、XOR、加法是封闭的，因此在 `2^63` 模环内反推，与完整 64 位的两个可能 lift 在低 63 位上完全等价。测试显式包含完整哈希最高位为 1 的名称，以及两种 lift 的一致性。

| 算法 | 剥离处理 |
|---|---|
| FNV、IW 资源、满 64 位别名、FNV32 | 按 profile 的完整比较位数逆运算 |
| secure | secret 在第一个 UTF-8 **字节**后注入；空 head 采用独立反向状态，不能把空 head 当作已经注入 secret |
| suffix | 先剥固定 secret，再剥候选后缀 |
| t7-script | 先逆掉最终额外乘法 |
| prime32 / DJB2 XOR / SAB SDBM | 按满 32 位环和各自逆式；SAB 保留反斜杠 |
| BO4/BOCW script、KVP | 保留既有全前向实现 |
| 截断到低 60 位 | 保留前向搜索，命中只作待核验候选；不能正式导出。32 位算法本身没有低 60 位之外的信息，勾选待核验选项仍不会让结果正式导出 |
| 偶数乘数、非标准比较掩码 | 不启用剥离 |

计划按完整槽边界拆成 head 与 tail，不切开 UTF-8 字节。选择器比较：

1. **反向目标表**：每个 tail 对目标集合反向一次，扫描时每个 head 前向一次。
2. **前向 head 表**：预先计算 head 状态，扫描时对相关 tail 和目标反向查询。

表项上限为 2,000,000；预计字节操作及前向次数没有足够收益时保留前向。显式 GPU 选择继续走设备前向扫描及 CPU 自检；此版没有宣称已实现 GPU 剥离。自动模式可以选择原生 CPU 剥离。

`scan(base, count)` 返回原计划的本地组合索引，消费的逻辑区间严格为 `[base, base+count)`。跨 head/tail 边缘、预算不足一个乘积块、暂停及断点游标不改变含义。每个命中仍须重新构造原名称并通过 Python digest，之后才进入冲突检查、Saluki 去重及 CDB 回读链。

## 本机性能记录

完整数据：`validation/peel-benchmark.json`。重跑：

```powershell
python scripts/benchmark_peeling.py --repeats 3 --threads 4
```

测试采用真实武器名称结构的自建组合：32,768 个 `rex_vm_ar_kilo2_*` 前缀 × 256 个 `inspect_empty_*` 后缀，共 8,388,608 候选；5 个完整目标。前向与剥离返回的全部索引相同。计时包含各自词表准备与扫描，使用三次完整运行的中位数。

| 指标 | 全前向 | 剥离 |
|---|---:|---:|
| 等价候选范围 | 8,388,608 | 8,388,608 |
| 实际前向状态哈希次数 | 8,388,608 | 32,768 |
| 后向字节操作 | 0 | 21,760 |
| 反向表项 | 0 | 1,280 |

实际前向次数减少 **256 倍**。墙钟收益应读取随源码一起生成的 JSON；它包含 Python 词表归一化/打包和表准备，不等于 256 倍。`hash_ratio` 与 equivalent candidates/s 只是工作量指标，不能写成实际 full-name hashes/s。测量脚本还验证目标集合密集、只有两个 tail 的无收益空间保留前向，并与普通前向命中完全相同。

Python `Plan.at + UTF-8` 另用 262,144 个名称测量。它只评估字符串生成，不包含哈希，不把小样本外推为全空间实测。当前原生 slot 热路径无需物化每个完整候选，因此没有把既有 crossassets 规则整体改写为另一套 Rust 规则；收益更明确的部分是移除逐候选拼串和重复前向尾段。规则解析、来源语义与 bounded search 留在 Python，便于后续维护。最终硬件、源文件 SHA 及生成速率均在 JSON 中记录。

## 估算的含义

估算在临时 SQLite 工作库中导入，使用与执行完全相同的候选准备函数。它不创建运行目录、CDB、CSV 或方法记录，也不改资产、名称索引或已有账本。社区首次下载和刷新是单独同步步骤：完成后估算只读固定快照缓存，估算本身不触发网络请求。

- `candidate_total`：所有计划的混合进制空间总和。不同规则可能重复猜同一名称，这仍是不同计划的候选工作量。
- `budgeted_candidates`：当前目标与已知缓存下的预算上界。执行找到名称后目标会缩小，可能提早停止。
- `cached_candidates_lower_bound`：当前完整指纹已证明扫过的范围；不能承诺发现新名后变化的目标子集也都能复用。
- `collision_expectation`：`budgeted_candidates × distinct_targets / 2^effective_bits`。分别使用 32、60、63 或 64 位；它是均匀随机假设下的偶然碰撞参考，不是成功率或“能找到多少名字”的预测。
- 小预算也付出反向表或 head 表的完整固定准备成本；不会按候选占比把准备成本错误缩小。
- CPU 标尺包含当前目标查询、profile 的 secret/最终乘法、三次样本中位数与 75% 占空比，同时估算词表打包成本。

时间范围是宽的 CPU 规划区间：计算参考的 0.1 倍至 4 倍加已观察准备时间。短样本线程启动、缓存探针、剥离表分配、命中后目标缩小都会改变耗时。GPU 初始化/吞吐、导出与 SQLite 保存没有通过该 CPU 标尺测定；该范围不是置信区间、SLA 或 GPU 速度承诺。时间预算警示把导入/候选准备时间也计入。

完整实测：`validation/estimate-validation.json`。重跑：

```powershell
python scripts/validate_estimate.py
python -m pytest tests/test_estimate.py tests/test_peel.py tests/test_registry_sync.py tests/test_methods.py
```

估算测量包含 6 个本地自建 CPU 场景：IW 63 位、FNV32、FNV64 的 37 项小预算、secure、suffix、KVP 前向。分别验证原候选空间与执行共享、实际预算、源文件与输出未变、实际计算落在展示区间。单元测试另外覆盖低 60 位、缓存下界、固定准备收费、未知域样本门控、社区缓存只读及取消清理；不把这 6 个场景当作所有机器的耗时保证。

## 指纹、复用与证据纪律

指纹包括按索引顺序归一化的槽、完整 profile 参数、目标键与类型、目录内容快照、方法版本与生成器源码 SHA、语料内容 SHA，以及影响结果的关键词、域、材质排除和截断选项。盘符、输出路径、任务 ID 和时间戳不进入语义指纹；复制同一数据到新盘仍可复用，任何实际内容或算法变化都会失效。

账本的 swept 表存半开区间。只有整个计算批次完成、命中通过独立回算且已持久化后，区间才可以标记覆盖。重跑恢复缓存命中，再对当前私有目标重新回算、重新排除 Saluki 已有完整键或精确名称，然后生成增量文件。仅跳过计算而不恢复命中会产生空导出，本实现不采用那种流程。

大语料实测发现，仅跳过扫描仍会重复解析数百万名称及重建数百个计划。完整运行缓存因此在解码名称库之前，逐文件流式计算内容 SHA，并检查当前目标类型/键、名称线索、注册表与相关实现源码。完整成功的证据包才可保存；预算不足、取消和失败不进入完整缓存。复用时验证整个证据包，再逐条独立回算和原子恢复，最后执行现有覆盖报告、冲突处理及增量导出。输入被替换、词典或名称线索变化会使缓存失效。仅变更输出盘符、预算或 CPU/GPU 后端不需要重新计算已完成的空间。

工作库的证据元数据迁移只执行一次，升级标记与加列、回填在同一事务中提交。真实数据库副本保留619条证据，349次重新打开耗时由19.12秒降至0.74秒。完整计划复用的目录实测由 `validation/adaptation-real-validation.json` 记录；其耗时包括重新验证、读取索引与导出，不能等同于零耗时。

连续零产出守卫限定同方法、版本、源码、算法配置、目标与参数作用域。暂停、取消、失败不证明方法耗尽；已扫完的缓存也不冒充一次新的完整零产出运行。覆盖守卫不免除哈希验证。

社区表行必须逐行回算。通过的源行只有在相同目标域、当前目标存在且完整键匹配时才可形成已验证证据；未匹配行、未知表和借用词表只作候选，不能排除真实新名或解锁 COD2026 未知域。仓库无许可证的完整社区表不随安装器再分发，也不自动向上游创建 PR。

## 开发与发布检查

1. 修改事实注册表后先生成文件；`--check` 失败时不能发布。
2. Rust、Python 与可用 OpenCL 必须通过独立参考向量；运行时注册表 SHA 也必须一致。
3. 剥离与前向逐索引比较，并保持暂停、预算、未知域、低 60 位、Saluki 去重回归。
4. 冻结版必须带生成器校验源码资源、注册表数据、原生 DLL、教程及许可证资料，不能依赖工作目录里的研究项目。
5. 正式安装器单独验证新电脑运行、估算/确认/执行、保存停止、缓存复用及增量 CSV/CDB；本地独立读取器验证不能替代真实 Saluki 界面加载声明。

参考项目只提供原理与工作流背景；本次原生剥离、计划收费、账本和表工具都是本地独立实现。
